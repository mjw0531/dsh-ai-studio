# dsh-ai-studio 设计蓝图

## 一句话

把 DSH 的会话、子代理、预设、工具和沙箱，组织成一家可审计、可回滚、以产物为中心的 **AI 工作室**。

## 边界

- Studio 是 DSH 插件，不是替代 DSH 的另一个运行时。
- Host 只依赖公开能力：`ctx.webServer`、`ctx.connection`、`ctx.agents`、`ctx.agentPresets`、`ctx.llm`、`ctx.tokenMeter`。
- Client 只依赖 `ctx.slots`、`ctx.layout` 和平台 React。
- 代码、文档放在项目仓库；任务、验收、证据、决策、运行记录放在 `studio.json`。
- 不在插件仓库内保存任何业务项目代码或业务数据。

## 核心对象

| 对象 | 作用 |
|---|---|
| Project | 一个项目：仓库、PRD、模块、预算、角色 |
| Role | 角色契约：使命、职责、决策权、模型路由、token 预算 |
| Task | 任务：验收标准、负责人、验收人、票类型、模块、契约 |
| Branch | 支线：任务对应的 Git 分支 |
| Acceptance | 验收项，必须全部完成才能 done |
| Evidence | 可复现证据：测试输出、命令、评审、验证记录 |
| Run | 一次 Agent 执行：prompt、输出、回执、token |
| Review | 独立评审：只读，返回 pass/fail + findings |
| Verification | Host 独立验证：命令、退出码、输出 |
| Decision | 项目级决策：结论、理由、不可逆标记、ADR 草稿 |
| MergeProposal | 合并提案：review → approved → merged |

## 工作流

1. 建项目、绑仓库、写验收标准。
2. 派单，Host 创建 `.worktrees/<taskId>` + `studio/<taskId>` 分支。
3. Agent 在 worktree 内实现，Host 自动提交改动。
4. Host 运行验证命令，记录退出码和输出。
5. 验收人 Agent 只读评审，返回 pass/fail。
6. 人勾验收、补证据、进入 done。
7. 人创建合并提案、批准、执行 `git merge`。
8. merge 后自动回归；失败升级为决策，可人工回滚。
9. 不可逆决策批准后生成 ADR 草稿，人工确认后写入 `docs/adr/`。

## 门禁

- 完成门禁：验收全 done + 至少一条 evidence。
- 评审门禁：代码任务 done 前必须有独立评审 pass。
- 文档门禁：项目绑定 PRD/INVARIANTS/MODULES 时，done 前必须 `docsSynced=true`。
- 验证门禁：没有通过的 Host 验证，不能提交合并提案。
- 契约门禁：越出模块契约/禁止路径时 blocked + 决策。
- 失败门禁：连续失败 2 次 → blocked + Architect 重拆 ticket。
- 合并门禁：只有 approved 提案、干净仓库、当前 base 才能执行 merge。
- 回滚门禁：只有 merged 且 post-merge 回归失败才能 revert。
- 不可逆门禁：`reversible=false` 的决策批准必须写结论和理由。

## 数据与迁移

- 数据文件：`%USERPROFILE%\.dsh\studio\studio.json`
- 页面「导出」生成完整 JSON 备份；「导入」先备份 `pre-import`，校验 schema 后替换。
- 代码和文档在项目仓库；迁移时分别复制仓库和状态文件，并重新绑定 `repoPath`。
- 更完整的项目打包在 v2.5 规划中。

## 兼容性

- 基准版本：DSH `0.2.1-rc.2`。
- 只使用公开 API；缺失能力时降级而不是崩溃。
- schema 变更有迁移链。
- 更高 DSH 版本是“尽力兼容”，不是“保证兼容”；升级后先跑 health 和 smoke。
