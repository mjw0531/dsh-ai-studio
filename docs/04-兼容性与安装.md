# dsh-ai-studio 兼容性、安装与升级

## 兼容性矩阵

| DSH 版本 | 状态 | 说明 |
|---|---|---|
| `0.2.1-rc.2` | ✅ 已验证 | v2.5.0 的基准版本；Web/桌面、Agent、评审、merge、dogfood 均在此版本验证 |
| `>= 0.2.1-rc.2` | ⚠️ 尽力兼容 | 不满足最低版本时 Host 会标记不支持；高于基准版本时只使用公开的 `ctx.webServer` / `ctx.connection` / `ctx.agents` / `ctx.agentPresets` / `ctx.llm` / `ctx.tokenMeter` / `slots` / `layout`，缺失能力降级 |
| `< 0.2.1-rc.2` | ❌ 不支持 | Host 仍会启动并给出兼容性警告，但 Agent/页面能力可能缺失 |

界面上「本地 · vX」旁若出现兼容性警告，先升级 DSH，再安装匹配的 Studio。

## 安装

1. 在 DSH 的 **Plugins → Add plugin** 选择 `mjw0531-dsh-ai-studio-2.5.0.tgz`。
2. 安装完成后**完全退出 DSH（含托盘）**，重新打开。
3. 左侧出现「AI 工作室」；打开后 Host 自动创建默认项目、角色和示例任务。
4. 访问 `http://127.0.0.1:<port>/studio-api/health`，确认：

```json
{ "ok": true, "pluginVersion": "2.5.0", "dshVersion": "0.2.1-rc.2" }
```

## 外部执行器

角色页可以把执行器切到 **Claude Code** 或 **Codex CLI**。前提：

- 本机已安装对应 CLI；
- 已在该 CLI 完成登录（`claude` / `codex login`）；
- 项目已绑定 Git 仓库（外部执行器只在 worktree 内跑）。

Studio 只负责在 worktree 内启动 headless 命令、收集输出、归一化回执；Host 验证、独立评审、人工 merge 仍然不可绕过。

## 数据位置与备份

- 数据文件：`%USERPROFILE%\.dsh\studio\studio.json`
- 页面右上角「导出」下载完整 JSON 备份（含 schemaVersion / pluginVersion / DSH 版本）。
- 手动备份：停止 DSH 后复制 `studio.json`；不要直接编辑运行中的文件。
- 页面「导入」：选择导出文件恢复；Host 先把当前文件备份为 `studio.json.pre-import-*`，校验 schema 后替换，不支持更高 schema。
- 损坏恢复：Host 会把损坏文件备份为 `studio.json.corrupt-*`，不会静默覆盖；把最近一次导出/备份替换回去，重启即可。

## 升级

1. 先导出备份。
2. 安装新 tarball，完全退出并重启 DSH。
3. Host 按 `schemaVersion` 自动迁移；迁移失败会保留原文件并给出警告。
4. 升级后检查 `/studio-api/health` 的 `pluginVersion`。

## 降级

- 新 schema 不保证能被旧版本读取。降级前先把数据导出，并删除/改名 `studio.json`，让旧版本重新 seed；或者手动把 `schemaVersion` 降到旧版本支持的版本（会丢新字段）。
- 生产环境建议只升级、不降级。

## 首次 5 分钟闭环

1. 打开「董事会」确认默认 Owner 角色。
2. 打开「任务」新建一个 `new` 票，填写验收标准、验证命令 `npm test`。
3. 绑定项目仓库（设置 → 仓库路径）。
4. 派单 → 等待 Agent 回执 → Host 验证 → 独立评审。
5. 验收完成后创建合并提案 → 批准 → 执行 merge → 查看 post-merge 回归。

## 已知限制

- 不自动 merge、不自动 push；merge 必须由人触发。
- 自动回滚策略未接入；只有人工回滚。
- Agent 的 shell 可能被 Windows ACL 阻断；Host 独立验证仍可运行。
- 金额成本没有真实报价时显示「待接入」。
- 跨厂商评审策略只是同族提示，不强制。
