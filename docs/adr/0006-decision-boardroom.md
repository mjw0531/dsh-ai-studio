# 项目级决策进入董事会，Agent 只能建议

## 背景

v0.4 的 Agent 回执已经包含 `decisions`，但这些建议只存在 Run 里，Owner 看不到，也没有批准/拒绝记录。用户要的是“赛博公司”的管理面：支线冲突和项目级约束必须由 Owner 拍板，不能由 Agent 口头决定，也不能只留在聊天里。

## 决策

新增 `Decision` 持久对象和独立“董事会”视图：

- Agent 回执中 `scope: "project"` 的决策自动创建 pending Decision；
- Owner 也可以手动提出决策；
- 只有 Owner 能 `approved` / `rejected`，必须记录结论和理由；
- 决策带 `runId` / `taskId` / `tokenCost`，可追溯到来源和成本；
- pending 决策进入公司仪表盘的“需要你”；
- 决策只能决定一次，重复裁决返回 `decision_decided`；
- v0.5.0 不自动生成 ADR，也不自动修改任务/契约。

## 考虑过的选项

1. **Agent 决定项目级事项**：快，但违背“人类持有最终决策权”，也无法审计。拒绝。
2. **只存在 Run.receipt**：实现最少，但 Owner 看不到、无法批准，也无法形成组织记忆。拒绝。
3. **独立 Decision + 董事会**（选中）：把“建议”和“决定”分开，符合公司治理，也为后续 ADR/Scope 门禁留下记录。

## 后果

- Agent 的输出从“聊天里一段话”变成“可裁决的对象”。
- 董事会是项目级冲突的入口，不是所有任务的审批流；任务验收仍在 Task Room。
- v0.5.0 的决策只是记录，不会自动改变任务、契约或 Git；真正的“批准后执行”留给 v0.6。
- 目前只有手动/Agent 提出，Branch 契约冲突的自动升级还没接。
