# 支线自动登记，同契约不同变更自动升级决策

## 背景

v0.5.0 的董事会只有 Agent/人工提出的决策，Branch 仍只是 Task 上的一个字符串。用户要的“支线汇入”必须知道：这条支线改了什么契约，另一条支线是否改了同一个契约。没有这层事实，冲突只能靠人记得。

## 决策

- 派单时自动登记 `Branch`（名称、目标、角色、契约键、状态）；任务没有分支名时使用 `task/<id>`。
- Agent 回执的 `contractDeltas` 写入 `contractChanges`，并记录到 Branch 的 `contractKeys`。
- 如果同一项目内另一条支线已对同一契约声明了**不同**变更，自动创建 pending Decision，标题 `契约冲突：<contract>`，选项列出双方变更。
- 该决策只能由 Owner 在董事会批准/拒绝；不自动修改代码或契约。
- 同一 Run 不重复生成同一冲突决策。

## 考虑过的选项

1. **只靠人记录契约冲突**：成本最低，但会漏；也法形成可审计的冲突记录。
2. **自动选一个变更**：快，但等于 Agent 替 Owner 做了项目级决策，违背决策门禁。
3. **自动升级到董事会**（选中）：机械、可审计、保留双方方案，把裁决权留给 Owner。

## 后果

- 契约冲突从“聊天里说一句”变成可持久化的 Decision。
- 分支只记录、不创建 Git branch/worktree；真正的代码隔离在 v0.6。
- 冲突检测只比较 `contract` 与 `change` 字符串；语义冲突、二进制资产冲突仍需 v0.6 的 worktree/diff 预检。
- Branch 由任务驱动，尚未支持手工创建/放弃；后续可补。
