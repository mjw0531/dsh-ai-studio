# 项目知识只读引用仓库原文，模块契约是独立实体

## 背景

工作流评审指出：Agent 需要的不是整份 PRD，而是「模块契约卡 + ticket + 不变量」；文档必须单一事实源，不能出现第二份正文。v0.7 只有 Task 上的 `module/contractRef` 字符串，没有模块对象，也没有项目文档入口。

## 决策

- Project 只保存 `prdPath / invariantsPath / modulesPath` 三个仓库相对路径，不复制正文。
- 知识页通过 Host 读取仓库文件；路径限制在 repo 根目录内，拒绝 `..` 越界。
- Module 是独立实体：职责、契约文件/摘要、允许/禁止路径、依赖。
- Task 的 `module` 按名称匹配 Module；派单时自动把模块职责、允许/禁止路径、契约摘要注入 Agent prompt。
- 文档读取失败/文件不存在时显示状态，不静默创建或覆盖文件。

## 考虑过的选项

1. **把 PRD 正文存进 studio.json**：会形成第二份事实源，且与 git 历史脱节。拒绝。
2. **只放路径，不提供查看**：Agent 仍需用户手动喂文档，工作流没有闭环。拒绝。
3. **路径 + 只读查看 + Module 实体**（选中）：单一事实源，且能把上下文喂窄。

## 后果

- 知识页依赖项目已绑定仓库；未绑定时不能读文档。
- 只读查看不会修改文件；文档编辑仍在编辑器/git。
- 还没有“实现者不许改契约”的强制拦截；契约变更仍靠 Agent 回执和决策。
- 还没有从 MODULES.md 自动导入模块；模块需要手动建或后续加解析器。
