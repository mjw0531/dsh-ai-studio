# 改修票必须先诊断和计划才能派单

## 背景

`kind=fix` 之前只是标签：可以直接派单让 Agent“边改边想”。工作流评审要求改修型先诊断、再计划、后修改，避免把模糊问题直接丢给实现者。

## 决策

- Task 增加 `diagnosis` 和 `plan`。
- `kind=fix` 的票在 `getDispatchContext` 时校验：两者必须非空，否则 `plan_required`，不能派单。
- 新建型（new）不受影响。
- 新建任务 UI 提供诊断/计划 textarea；fix 票缺一项前端直接拦截。
- Task Room 显示诊断/计划；Agent prompt 带上这两段。
- 诊断/计划可以由人或 Architect 填写；Agent 不能替 Owner 决定问题范围。

## 考虑过的选项

1. **只做 UI 提示**：没有强制，派单仍可绕过。拒绝。
2. **自动让 Agent 先诊断再执行**：诊断本身也需要上下文和判断，且会绕过人。拒绝。
3. **派单前硬门禁**（选中）：最直接，保证改修票不会无计划开工。

## 后果

- 改修票多一步填写，但能减少“边改边猜”。
- 已经存在但未填写的 fix 任务会派单失败，需要补字段。
- 诊断/计划是自由文本，没有结构化校验；后续可做模板/必填项。
- 新建型 red→green 仍没有强制测试先行；v2.0 再补。
