# 失败必须产生重拆票，集成验收必须有独立票

## 背景

v0.9 连续失败 2 次会 blocked + 决策，但只有决策，没有可执行的后续任务；集成/playtest 只存在于文档里，没有 Task 标记。结果是失败停在董事会，集成靠口头约定。

## 决策

- Task 增加 `integration: boolean`：标记“打包可玩 + 人玩 10 分钟”的集成/playtest 票；它仍走同样的验收/证据门禁。
- Task 增加 `originTaskId`：记录重拆票的来源，防止无限重拆。
- 连续失败 2 次时，除生成决策外，自动创建一个 backlog 重拆票：
  - owner 为该项目的 Architect（找不到则回退原负责人）；
  - `kind=fix`，验收是“重拆任务/契约 + 可执行 ticket”；
  - 不允许系统自动派单，必须由人批准后启动。
- 同一原任务只生成一次重拆票；后续再失败仍 blocked，但不再重复生成。

## 考虑过的选项

1. **只生成决策**：决策不会自动产生工作，容易停在董事会。拒绝。
2. **自动重派原任务**：违反“失败 2 次不许原地重试”。拒绝。
3. **自动生成并自动派单重拆票**：Architect 的重拆也需要人确认范围和契约，自动派单会放大错误。拒绝。
4. **生成 backlog 重拆票 + 人工批准**（选中）：把动作落到任务板，但不绕过人的 gate。

## 后果

- 失败后有明确下一步，不再只是“待处理决策”。
- 重拆票不会自动运行；Owner/Architect 仍需批准。
- 集成票目前需要手动创建；每 N 个任务自动生成的规则留到 v1.1。
- 数据 schema v10 增加两个字段；旧版本可忽略额外字段，但新版本迁移会补齐。
