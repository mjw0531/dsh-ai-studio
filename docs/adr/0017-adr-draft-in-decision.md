# ADR 草稿保存于决策记录，不自动写仓库

## 背景

v1.3 要求不可逆决策批准时写理由，但理由留在董事会，不会变成可审阅的架构决策记录。直接自动写 `docs/adr/NNNN-*.md` 会修改用户仓库、需要编号/路径/冲突处理，风险大。

## 决策

- Decision 增加 `adrDraft: string | null`。
- 不可逆决策批准时，Host 根据标题、背景、结论、理由、建议生成 Markdown 草稿，保存到 Decision。
- 草稿不自动写仓库；董事会历史卡片可展开查看。
- 编号/文件名/落盘位置由人决定，避免自动覆盖已有 ADR。
- 可逆决策不生成草稿。

## 考虑过的选项

1. **自动写 docs/adr/**：会改仓库、需要编号与冲突处理，且不可逆决策应由人审阅。拒绝。
2. **只保留理由文本**：无法直接转成 ADR。拒绝。
3. **生成草稿存记录**（选中）：可审阅、可复制，不碰仓库。

## 后果

- ADR 草稿可能长期留在记录里，需要人手动落盘；后续可加“写入仓库”按钮（仍需确认）。
- 草稿是确定性模板，不是 AI 生成，质量受 Decision 字段影响。
- 已批准的旧决策迁移后 adrDraft 为 null，不会补生成。
