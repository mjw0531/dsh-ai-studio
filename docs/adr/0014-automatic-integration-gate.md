# 集成票按完成任务数自动生成，但不自动派单

## 背景

v1.0 允许手动标记集成/playtest ticket，但没有任何规则保证它会出现。工作流评审要求每 N 个 ticket 插一个“可玩 build + 人玩 10 分钟”的集成 gate。

## 决策

- 每次任务进入 `done` 时，统计该项目已完成任务数。
- 每 3 个完成任务自动创建一张 `integration: true` 的 backlog 任务：
  - 标题 `集成验收（自动 #N）`；
  - owner=Lead，reviewer=Verifier；
  - 验收：打包可运行 build；人玩 10 分钟并记录阻断问题。
- 通过标题前缀计数去重；第 3、6、9… 个完成任务各生成一张。
- 不自动派单、不自动执行、不替代单任务验收；人仍需批准/运行。
- 手动集成票不计入自动序号，避免互相干扰。

## 考虑过的选项

1. **按时间每周生成**：与任务节奏脱节，可能没有可玩的增量。拒绝。
2. **每次 done 都生成**：太频繁，集成票会淹没任务板。拒绝。
3. **按完成任务数每 3 个生成**（选中）：与交付节奏对齐，且数量可控。

## 后果

- 集成票会出现在 backlog，需要人安排；不会自动占用 Agent/token。
- 如果集成票长期不处理，任务板会积累；需要后续加“集成票超期提醒”。
- 阈值 3 是固定值，还不是项目配置；后续可做 project setting。
- 完成任务数包含历史种子任务，第一次可能立即触发；这是预期行为。
