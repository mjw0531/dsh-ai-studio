# 产品审查摘要

> 来源：2026-11-13 对 v3.14.2 的外部深度审查；本文件是脱敏、去外链、按当前版本复核后的摘要。
> 当前基线：v3.20.4 / schema 41。
> 原始文档不进入 Git。

## 1. 审查范围

- 阅读 README、AGENTS.md、CONTEXT.md、设计蓝图、迭代计划、使用说明书与相关 ADR。
- 类型检查与 96 个 Host 测试。
- 三条并行审计：状态存储、前端旅程、Host 安全与健壮性。
- 对状态损坏、导入校验、门禁批准、合并前置检查、失败计数等关键结论做了代码复核或复现。
- 未运行完整界面；前端旅程以代码推演为主。

## 2. 核心结论

1. **产品重心与真实需求错位。**
   过去的投入集中在“管住 AI 如何合并代码”，而核心需求是“把 PRD 变成架构，再变成任务”。主流程恰好落在工具里最空的一段。

2. **会议是一座孤岛。**
   参会 AI 看不到 PRD 正文和完整角色卡；会议结论写不回文档；会议只能关联已有任务，不能生成任务草案。

3. **会议原则只实现了一半。**
   原原则是“会议产出经 Owner 采纳后写入 PRD / 决策 / 任务”。实际只做了决策一条路，PRD 和任务两条路没有做。

4. **重门禁来自多轮外部意见叠加。**
   门禁单看都合理，叠加后越靠近 Git 越硬，越靠近规划越软，与“规划错误代价最大”相反。

5. **存在数据安全缺陷。**
   状态文件校验失败会被挪走并重建演示数据；保存回退先删主文件；导入先改内存后校验。

6. **流程从未在真实项目上跑完。**
   提交与版本密集，功能增速远超验证速度；没有真实闭环证据。

## 4. 仍未解决

| 问题 | 影响 | 建议 |
|---|---|---|
| npm 仍停在 3.12.0 | 外部用户装到旧缺陷版本 | 本地 `npm login` 后发布，或先在 npm 弃用旧版 |
| 运行记录只归档不裁剪 | `studio.json` 会持续增长 | 归档后裁剪，保留摘要与文件引用 |
| Run 无取消 | 长任务只能等超时 | 增加取消与重启对账 |
| 任务抽屉/合并页签双入口 | 语义冲突 | 合并只保留一个入口 |
| 真实切片未跑 | 无法判断门禁成本 | 用非外部敏感项目跑完整闭环 |
| 客户端 E2E 仍薄 | UI 回归靠手测 | 补首次安装、派单失败、会议闭环 |
| 版本号仍偏密 | 版本像存档点 | 改为阶段版本，减少 tag |

## 5. 四条原则

1. **先减后加。** 冻结新功能，收起单人用不上的界面。
2. **AI 起草，Owner 确认。** 门禁是“确认”动作，不是“禁止生成”。
3. **文档是主角。** 规划产物以 Markdown 存在于项目仓库，是唯一真源。
4. **门禁建在 Owner 能判断的证据上。** 构建、测试、可运行版本、白话摘要。

## 6. 对当前版本的判断

- 数据安全和会议输入/输出已明显改善；
- 规划文档、任务依赖、里程碑、会议材料、复盘、开局向导、搜索已落地；
- **真正的里程碑自动流水线与真实切片仍未完成**；
- 下一步应优先发布收口和真实闭环，而不是继续增加页面功能。
