# 研发路线摘要

> 来源：2026-11-13 外部迭代计划；本文件脱敏、去外链，并按 v3.20.4 的实际交付重写。
> 原始文档不进入 Git。

## 1. 目标工作流

```text
立项 → 完善 PRD → 架构设计 → 技术验证
→ 任务拆分 → 研发循环 → 里程碑验收 → 变更回流
```

Owner 只在三处介入：

1. 确认规划草案；
2. 处理升级上来的异常；
3. 做里程碑的运行验收。

规划产物留在项目仓库，运行记录留在仓库外。

## 2. 规划产物的真源

```text
<项目仓库>/docs/
├─ PRD.md                    需求，R- 编号
├─ ARCHITECTURE.md           架构
├─ INVARIANTS.md             不变量，保持短小
├─ modules/<模块>.md          模块卡
├─ adr/NNNN-标题.md           不可逆决定
├─ meetings/日期-类型.md      会议纪要
└─ plan/
   ├─ milestones/M1.md       里程碑、任务、试运行清单
   └─ tasks/T-0012.md        任务卡
```

| 内容 | 真源 | 另一处 |
|---|---|---|
| PRD、架构、不变量、模块卡、ADR | 仓库文件 | Studio 只读 |
| 会议纪要、里程碑、任务卡定义 | Studio | 仓库是发布件 |
| 任务状态、Run、评审、验证、token | Studio 状态文件 | 不进仓库 |

## 3. 三条分支

- **主干**：Owner 确认规划文档或验收里程碑时才前进；
- **集成分支**：任务成果汇合，每次合入先验证；
- **任务分支**：每个任务独立 worktree。

不自动 push，不自动合并到主干。

## 5. 原计划的六条规则改写

| 原规则 | 方向 |
|---|---|
| 不把状态写进项目仓库 | 规划定义进仓库，运行记录不进 |
| 不做自动任务生成 | AI 起草，Owner 确认后批量创建 |
| 真实 merge 只能人触发 | 主干人工；集成分支可自动 |
| 验证通过不自动完成 | 普通任务自动到待合并；关键任务人工 |
| 每 3 个任务一张集成票 | 由里程碑验收取代 |
| 连续失败 2 次阻塞 | 带失败原因返工，轮数可配 |

底线不变：

- 实现任务的 AI 不能给自己验收；
- 会议产出必须经 Owner 采纳；
- 主干只在确认后前进；
- 不可逆决定必须由 Owner 批准。

## 6. 下一步

### P0：发布收口

- 本地 `npm login`；
- 发布当前版本到 npm；
- 空 profile 安装验证；
- 对齐 README、Release、npm、CI。

### P0：真实切片

选一个非外部敏感、可运行的小项目，跑：

```text
建档 → 规划 → 任务 → 派单 → 验证 → 评审
→ 合并提案 → 人工合并 → 复盘
```

只修阻塞，不加功能。

### P1：可靠性

- Run 取消与重启对账；
- 归档后裁剪；
- 客户端 E2E；
- 合并入口统一。

### P2：后续候选

- 里程碑自动流水线；
- 自定义模板；
- 任务批量指派；
- 会议行动项与任务双向状态。

## 7. 明确不做

- 不自动 push；
- 不自动合并到主干；
- 不用演示数据覆盖真实数据；
- 不为降低门禁删除关键任务评审；
- 不把运行记录写进项目仓库；
- 不在未跑通真实切片前继续扩张功能面。
