# 对话补充与产品方向

来源：用户与 DeepSeek 的分享对话（2026-10-21）以及本轮“赛博公司”讨论。外部内容只作为设计输入，竞品结论尚未逐条核实。

## 1. 对象模型再确认

工作台不是聊天界面，而是**对象中心**的界面。一等公民：

- **Project**：目标、里程碑、约束库、成员。
- **Branch**：一条支线/工作包，有状态、可见文件集、绑定角色、汇入契约；在 UI 里是看板卡片或工作区，不是一段对话。
- **Artifact**：代码 diff、文档、测试报告、架构图。
- **Decision**：从支线汇入主线的结构化事实，进入项目记忆库，后续支线按条件召回。
- **Role**：权限与工具集的配置，不是聊天角色。

聊天框只能作为某个 Branch 工作区里的辅助面板，不能当主界面。这与当前 Studio 的 Mission Control / Task Room 方向一致。

## 2. 支线结果包

支线结束时，主线不应该消费整段对话，而应该消费一个结构化结果包：

```json
{
  "artifacts": [
    { "kind": "diff", "path": "src/ability/cooldown.ts" },
    { "kind": "test", "path": "reports/ability-test.txt" }
  ],
  "decisions": [
    {
      "title": "冷却按固定 tick 计算",
      "rationale": "避免不同帧率下行为漂移",
      "scope": "project"
    }
  ],
  "contract_deltas": [
    {
      "contract": "docs/contracts/ability.md#cast-timing",
      "change": "cast 前摇从 0.2s 改为 3 tick"
    }
  ],
  "rejected_options": [
    {
      "option": "按真实时间累加冷却",
      "reason": "联机回放不可复现"
    }
  ]
}
```

当前 Studio 的 Merge Proposal 已覆盖 `summary / risk / rollback / reviewNote / mergeCommit`，下一阶段应补 `decisions`、`contract_deltas`、`rejected_options`。这比在 UI 里多画一个字段更重要：它决定主线能不能在不读支线全文的情况下继续做对决策。

## 3. 决策升级机制

最难的不是“记录决策”，而是判断**哪些支线决策必须升级为项目级约束**。

建议的判据：

- 影响多个模块/角色 → 升级；
- 改变接口契约 → 升级；
- 不可逆或回滚成本高 → 升级；
- 只影响当前支线的实现细节 → 留在支线。

升级必须经过一个显式门禁：支线负责人提出 → Architect/负责人裁决 → 写入 Decision/ADR → 后续支线可见。没有这个门禁，支线越多，契约漂移越严重。

## 4. 可见性即权限

验收者不应该看到实现者的完整推理过程，否则验收会被实现者的自我解释污染。这不是 UI 隐藏，而是 Scope/上下文隔离：

- 实现支线：任务切片 + 接口契约 + 约束。
- 验收支线：验收标准 + 实现产物，不加载实现支线的对话。
- 主线：约束 + 汇入摘要 + 决策，不加载支线全文。

DSH 的 Session/Subagent 和 preset 机制可以实现这一点；Studio 需要把“可见性”从 UI 配置提升为领域规则。

需要重点验证的问题：

- 它们是否做到“支线目标即契约 + 负责人仲裁”？
- 是否有真正的 Scope 隔离，而不只是 UI 隐藏？
- 汇入时是否记录 `decisions / contract_deltas / rejected_options`？
- 是否能在 DSH 插件形态下复用？

## 6. “赛博公司”与 Owner Dashboard

用户的核心感受是：这不是一个工具，而是“我出钱让 AI 给我开发项目”的公司。因此需要老板视角的仪表盘，而不只是项目经理视角的任务板。

三层信息架构：

1. **Owner Dashboard（公司层）**：项目组合、待决策、预算/产能、风险、交付流。
2. **Mission Control（项目层）**：任务、验收、合并队列、团队负载。
3. **Task Room（任务层）**：对话、产物、验收、上下文。

Owner Dashboard 的第一版只做真实数据：

- 项目组合健康、WIP、待验收、待合并、阻塞、停滞；
- “老板收件箱”：合并审批、范围决策、预算异常、权限变更；
- 角色负载与项目阶段；
- 交付流（已验收/已合并/playtest）；
- 风险雷达（老化合并、缺证据、长期无更新）。

预算/成本/ROI 在 Agent 执行与 token 计量接入前明确显示“待接入”，不编造金额。v0.3 已实现公司级聚合、老板收件箱、项目组合、角色负载、风险雷达和交付流；v0.4 已接入真实 DSH token 消耗，金额仍等报价。
