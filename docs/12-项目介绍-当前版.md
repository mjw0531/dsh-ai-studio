# dsh-ai-studio 项目介绍（当前版）

> 版本：**v3.2.1**
> DSH 基线：**0.2.1-rc.2**，当前验证：**0.2.1-rc.5**
> 数据 schema：**26**

## 1. 一句话

**dsh-ai-studio 是 DeepSeek Harness 的即装即用插件，把 AI 聊天窗口变成一间可审计、可验证、可回滚的 AI 工作室。**

它不是“让 AI 写一段代码”，而是管理：

- 谁负责；
- 在什么阶段；
- 用什么执行器和模型；
- 按什么验收标准；
- 经过哪些门禁；
- 产出什么证据；
- 由谁批准合并。

## 2. 它解决什么问题

普通 AI 编程链路：

```text
人提需求 → AI 改代码 → 人自己看 → 可能直接提交
```

问题：

- AI 说“改好了”，但没有可复现证据；
- 改坏主工作区；
- AI 自己检查自己；
- 多任务并行时分支和契约冲突；
- 决策没有记录；
- 换电脑后状态丢失。

Studio 的闭环：

```text
公司组合
  → 项目阶段门禁
  → 角色契约
  → 任务与验收
  → 独立 worktree 执行
  → Host 验证
  → 独立评审
  → 人工验收
  → 人工 merge
  → 合并后回归
  → 失败升级 / 决策 / 回滚
```

## 3. 系统结构

```text
DSH Web / Desktop
  ├─ Client Plugin
  │    ├─ 公司：项目组合、预算、优先级、角色覆盖
  │    ├─ 决策台
  │    ├─ 知识：PRD / INVARIANTS / MODULES
  │    ├─ 项目：阶段门禁、Trigger、Workshop、Demo
  │    ├─ 任务：看板、任务抽屉、评审、验证、合并
  │    ├─ 合并队列
  │    ├─ 团队：角色、Provider Profile
  │    └─ 设置
  └─ Host Plugin
       ├─ /studio-api（同源、Bearer token）
       ├─ StudioStore（studio.json + 领域 service）
       ├─ Agent dispatcher
       ├─ Host verification
       └─ Merge / decision / trigger / workshop 治理
```

### 两个边界

| 部分 | 职责 | 不做 |
|---|---|---|
| Host | API、状态机、门禁、派单、验证、合并、持久化 | 不自动 push，不把数据接口改成免 token |
| Client | 展示和操作 | 不直接读写 `studio.json`，所有操作走 API |
| 项目仓库 | 真实代码、文档、Git 历史 | Agent 不能直接改主工作区 |

## 4. 核心对象

| 对象 | 含义 |
|---|---|
| Project | 一个仓库 + 一套知识文档 + 角色 + 任务 |
| Role | 职责契约：使命、职责、非目标、决策权、模型、执行器、预算 |
| Task | 一条可验收的工作，不是一句“帮我改一下” |
| Acceptance | 必须逐条完成的验收条件 |
| Evidence | 可复现证据：测试输出、命令、评审记录、验证记录 |
| Run | 一次 Agent 执行记录：prompt、输出、回执、token |
| Verification | Host 在 worktree 执行命令的退出码和输出 |
| Review | 独立验收人 Agent 的只读检查 |
| Decision | Owner 级项目决策，必须留结论和理由 |
| Merge Proposal | 合并申请：摘要、风险、回滚、分支、base |
| Module | 代码模块契约：职责、接口、允许/禁止路径、依赖 |
| Branch / Worktree | 每个任务独立的 Git 分支和检出目录 |

### 任务状态机

```text
backlog → ready → running → review → done
              ↘ blocked ↗
```

允许的流转由 Host 强制，UI 不能跳步。

## 5. 端到端工作流

### 5.1 公司层

Owner 打开「公司」：

- 项目组合健康度；
- token 预算与消耗；
- 超预算 / 未配置预算；
- 跨项目优先级；
- 角色覆盖；
- 老板收件箱：决策、阻塞、缺证据、老化合并。

公司层是 `StudioState` 的派生视图，不保存第二份事实。

### 5.2 项目阶段

```text
discovery → architecture → prototype → development
```

进入下一阶段必须经过 Stage Gate：

- Owner 完成检查项；
- 登记产物；
- 写门禁说明；
- 可显式豁免，但留审计记录。

代码项目只有 `development` 才能派单；从 `prototype` 进入 `development` 前必须有 `demo` 产物或 `passed` 的手动 Demo 记录。

### 5.3 角色与执行配置

角色不是人设，而是职责契约：

- 使命 / 职责 / 非目标；
- 决策权；
- DSH / Claude Code / Codex 执行器；
- Provider Profile；
- token 预算。

Provider Profile 只保存执行配置，不保存密钥。

### 5.4 事件入口

外部事件先进入 Trigger Inbox：

- 手动捕获；
- GitHub / CI / IM Webhook；
- HMAC-SHA256 验签；
- source / repo / label / author / mention 确定性过滤；
- 同一 `threadKey` 归入 Thread；
- 人工确认后才转 Task。

Webhook 不会自动派单，也不会自动 merge。

### 5.5 任务执行

1. Owner 建任务，写目标、负责人、验收人、验收标准；
2. 派单后创建独立 worktree：`.worktrees/<taskId>`；
3. 分支：`studio/<taskId>`；
4. Agent 只能在 worktree 内改代码；
5. Agent 回执必须包含非空 `summary` 和至少一条 `evidence`；
6. 回执缺字段时 Run failed，任务退回。

### 5.6 Host 验证

Host 在 worktree 内执行验证命令：

- 记录命令、工作目录、退出码、输出；
- 通过只写 evidence；
- 不自动勾验收项；
- 不自动 done。

### 5.7 独立评审

代码任务完成前：

- 验收人角色另开 Agent；
- 只读 diff / Host 验证输出；
- 返回 pass/fail 和 findings；
- 没有通过的独立评审，任务不能 done。

### 5.8 完成门禁

任务进入 `done` 前必须：

- 所有 acceptance 为 done；
- 至少一条 evidence；
- 代码任务有通过的独立评审；
- 项目绑定文档时 `docsSynced=true`。

### 5.9 合并治理

```text
done → merge proposal review → approved → merged
```

- 只有 `done` 任务能提合并；
- 提案记录摘要、风险、回滚、分支、base、验证；
- 真实 `git merge` 由人触发；
- 冲突必须 abort；
- 不自动 push；
- merge 后必须跑回归；
- 回归失败生成决策，可人工 revert。

### 5.10 决策与 Workshop

决策：

- Agent 只能提出；
- Owner 批准 / 拒绝；
- 必须留结论和理由；
- 不可逆决策必须有理由；
- 批准后可生成 ADR 草稿，写仓库由人触发。

Workshop：

- 多角色独立意见；
- AI 独立评审；
- AI 汇总只是草稿（共识 / 分歧 / 未决 / 候选）；
- 不覆盖原始意见；
- Owner 汇总后才能决策。

## 6. 门禁清单

| 门禁 | 作用 |
|---|---|
| 完成门禁 | acceptance + evidence |
| 阶段门禁 | 只能由 Owner 推进 |
| Trigger 门禁 | 人工确认才转任务 |
| Webhook 门禁 | HMAC + 确定性规则 |
| Workshop 门禁 | AI 意见不等于 Owner 决策 |
| Provider 门禁 | Profile 不含密钥；被绑定不能删 |
| 评审门禁 | 代码任务必须独立评审 pass |
| 合并门禁 | done → review → approved → merged |
| 合并执行 | 人触发、冲突 abort、不 push |
| 回归门禁 | merge 后必须跑验证 |
| 回滚门禁 | 只允许 `git revert -m 1` |
| 导入门禁 | 先备份、校验 schema、失败不覆盖 |
| 鉴权 | `/studio-api` 全部 Bearer token |

## 7. 数据与持久化

| 数据 | 位置 |
|---|---|
| 治理状态 | `%USERPROFILE%\.dsh\studio\studio.json` |
| 代码 | 项目仓库 |
| 文档 | 项目仓库 |
| 任务分支 | `studio/<taskId>` |
| 隔离工作区 | 项目仓库 `.worktrees/<taskId>` |

首次运行自动 seed 示例项目。损坏时备份而不是静默覆盖。

## 10. 它不是什么

- 不是另一个大模型；
- 不是 IDE；
- 不是自动 merge 工具；
- 不替代 DSH；
- 不支持在 Studio 里填模型 API Key；
- Claude Code / Codex 需要本机已登录；
- PWA / 独立窗口暂缓。

## 11. 安装

桌面端：

```text
Plugins → Add plugin → 本地目录 D:\dsh-ai-studio\packages\dsh-studio → Enable now → 刷新
```

Web profile：

```powershell
dsh plugin --profile web add "D:\dsh-ai-studio\packages\dsh-studio"
dsh --profile web
```

分发安装包：

```text
packages/dsh-studio/dsh-ai-studio-3.2.1.tgz
```
