## 2. 版本路线

### v2.15 Provider 实时探测

**目标**：把“历史健康度”补成“当前可用性”。

范围：

- 检查 DSH provider 是否存在；
- 检查模型是否在 provider 的模型列表里；
- 外部执行器检查 CLI 是否可执行；
- 返回最近一次探测时间、结果、错误；
- 仍不自动切换。

验收：

- 不存在的 provider/model 明确报错；
- 探测失败不影响已有任务数据；
- 不把探测结果写成 Run；
- 不自动改绑角色。

非目标：

- 不做真实模型推理探活；
- 不做自动 failover。

规模：**M**

---

### v2.16 Trigger Webhook 与语义过滤

**目标**：让 Studio 真正成为事件入口，而不是手工收件箱。

范围：

- GitHub / CI / IM Webhook 适配器；
- 签名校验 / 来源白名单；
- 确定性规则过滤（仓库、标签、作者、@）；
- 可选的 LLM 语义过滤；
- 同一 Thread 关联到已有 Task；
- 所有事件保留审计。

验收：

- 无效签名拒绝；
- 重复 externalId 去重；
- 规则不命中时只记录、不建任务；
- 人工确认后才转 Task；
- 不自动派单、不自动 merge。

非目标：

- 不做任意 Webhook 转发；
- 不做多租户事件隔离；
- 不做“事件直接改代码”。

规模：**L**

---

### v2.17 Prototype 手动 Demo 记录

> 自动 Demo 仍不做。

**目标**：把 Demo 从“一个路径字符串”变成可复核的记录。

范围：

- Demo 入口 URL / 本地路径；
- 启动命令（仅记录，不由 Studio 执行）；
- 验证步骤；
- 实际结果：通过 / 失败；
- 截图或录像路径；
- 已知限制；
- 记录人和时间。

验收：

- 进入 development 前仍要求 demo 产物；
- 手动 Demo 记录可作为 demo 产物；
- 记录不可静默改写；
- 不执行命令。

非目标：

- 不启动进程；
- 不检测端口；
- 不自动截图。

规模：**M**

---

### v2.18 Workshop 自动汇总

**目标**：减少 Owner 手工整理意见的成本，但保留最终决策权。

范围：

- 汇总各角色意见；
- 标出共识、分歧、未决问题；
- 生成候选方案；
- 明确“不建议自动采纳”；
- Owner 可以编辑汇总；
- 不自动写决策。

验收：

- 汇总失败不影响原始意见；
- 原始意见不可被汇总覆盖；
- AI 汇总不能直接变成 Owner 决策。

规模：**M**

---

### v2.19 Studio Shell / PWA / 引导

**目标**：让插件从“一个页面”变成可日常使用的工作台。

范围：

- 首次使用引导；
- 项目模板（游戏 / Web / 工具）；
- 独立窗口 / PWA 可选；
- 快捷入口与空状态；
- 版本兼容提示；
- 安装、升级、回滚说明。

验收：

- 新用户 5 分钟内能建项目、角色和第一个任务；
- 不依赖桌面私有协议；
- 没有 PWA 时页面仍可用。

规模：**L**

---

### v3.0 公司级组合治理

**目标**：从单项目工作台升级到多项目组合管理。

范围：

- 多项目预算与产能；
- 跨项目优先级；
- Owner 决策队列；
- 风险与阻塞聚合；
- 团队角色跨项目复用；
- 导出公司级报告。

验收：

- 公司视图只从项目状态派生；
- 不引入第二份事实来源；
- 单项目仍可独立使用。

规模：**L**

## 3. 优先级建议

```text
v2.15  实时探测（低风险，补齐可观测性）
v2.16  Trigger Webhook（高价值，风险中等）
v2.17  Prototype 手动 Demo（低风险，补齐阶段证据）
v2.18  Workshop 自动汇总（中价值，风险中等）
v2.19  Studio Shell / PWA（体验）
v3.0   公司级组合治理（平台化）
```

如果只能选一个：

> **v2.16 Trigger Webhook** 对“赛博公司”的产品形态提升最大。
> 但它需要签名、鉴权、幂等和适配器，风险也最高。

如果优先稳定性：

> **v2.15 实时探测** 和 **v2.17 手动 Demo 记录** 风险最低，能先把治理闭环补完整。

## 6. 外部反馈整改计划（v3.5.0 → v3.6.0）

### 6.1 来源与结论

三份输入：

1. [外部电脑首次安装/首次派单 400](https://chatglm.cn/share/KFpf9pCf)：前端把空分支发成 `null`，后端 `asOptionalString` 只接受 `undefined`。
2. [PRD 阶段工作流批评](https://chat.deepseek.com/share/4hopb1qxushb1c50aj)：发散与收敛混在一起，缺少 PRD 冻结判据、领域模型翻译层、可审计的需求决策。
3. 外部深度剖析（`D:\xwechat_files\...\dsh-ai-studio深度剖析.md`，分析基线 v3.2.1）：鉴权/命令执行、评审只拿到 diffstat、超时与回执解析、契约护栏时序、状态文件膨胀、无 CI、文档自我矛盾、版本号通胀、单人门禁税。

状态说明：

- 深度剖析中的 `/boot` `Origin: null`/`file://` 绕过、项目包全量覆盖、taskId 穿越、提交绑定、schema 降级、全局 Git 身份，已在 **v3.3.0** 修复。
- 评审/Workshop 只读工具限制已在 **v3.4.0** 修复。
- 仍开放的问题按下面优先级进入计划。
